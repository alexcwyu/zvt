Design decisions

Decision Rationale Tradeoff Evidence
Use schema/provider routing before obtaining a storage engine. The same market schema can be accessed through configured storage backends. The reviewed routing layer does not validate backend installations or existing datasets. get_db_engine (L49)
Keep factor computation state separately persistent. Entity-level factors can update incrementally and save computation state. State/data write failures are handled per entity and require operational monitoring. Factor.compute (L434) / Factor.persist_factor (L571)

Workflow

Representative source-backed flow

Signal generation and simulated execution are separated by a trader interval. This is not same-timestamp fill accounting. Daily current-day inputs may also wait on wall-clock time even when real_time=False.

Diagram source

  W1["Commit converted domain records through the data session."]
  W0 --> W1
  W2["Compute factors and persist data/state."]
  W1 --> W2
  W3["At the next trader timestamp, dispatch the previous timestamp signal batch to the simulated listener before current factor/target processing"]
  W2 --> W3
  W4["Process current targets and queue buy/sell signals for a following timestamp, the final batch has no explicit post-loop dispatch in Trader.run"]
  W3 --> W4

Strengths and limits

Strengths

  • Recorders, factors and trading listeners form explicit boundaries rather than a monolithic exchange engine. Trader.init (L29) / Trader.run (L434) / Trader.on_trading_signals (L364) / Factor.compute (L434) / Factor.persist_factor (L571) / TimeSeriesDataRecorder.run (L476) / TimeSeriesDataRecorder.persist (L433)

Limitations

  • Trader real_time does not imply a live account: the constructor always creates SimAccountService. Trader.init (L29) / Trader.run (L434) / Trader.on_trading_signals (L364)
  • QMT fixed-price stock order integration depends on xtquant and an externally configured account. QmtStockAccount.order_by_amount (L154)
  • Default Trader.run dispatches previous-interval signals before new target generation; the final queued batch has no explicit post-loop dispatch. Hooks and overrides may implement different behavior. src/zvt/trader/trader.py (L456) / src/zvt/trader/trader.py (L511)
  • A daily run containing the current date enters a 600-second sleep before checking wall-clock hour, and repeats until hour>=19 even with real_time=False, because the daily branch precedes the real_time elif. src/zvt/trader/trader.py (L467)
